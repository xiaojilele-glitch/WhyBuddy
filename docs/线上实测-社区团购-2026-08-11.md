## 二、问题：选材层塌了，而且找到根因了

产物里 12 处摆放只用到 **8 种区块，全部来自前 30 名**：

    RecordDetail ×4（名次 16）   DataTable ×2（6）    WorkflowTimeline ×1（13）
    ActivityFeed ×1（5）        KanbanBoard ×1（29）  SearchBox ×1（12）
    RankedList ×1（4）          ScheduleCalendar ×1（30）

    名次最深 30｜中位 13｜**>52 名的：0 个**

**这正是当初做窄化要治的那个病。** 而窄化在这一趟**自己把自己关掉了**——本地用同一道题复现，日志原文：

```
[block_narrowing] 检索置信度 0.106 < 0.200（目录里没有对题区块）——本次不窄化，注入全量 315 个
```

于是回到未窄化的世界：315 个名字一句话 + 5 万 token 细节，模型只读得进头部。

### 对照实验：尺子没坏，是目录没覆盖

| 题目 | 窄化 | 说明 |
| --- | --- | --- |
| 告警值班 | 生效，选 30（27 个 >52 名） | 目录覆盖域 |
| 数据同步连接器 | 生效，选 33（31 个 >52 名） | 目录覆盖域 |
| 会议室预订 | 生效，选 57 | 半覆盖 |
| **社区团购** | **退回全量 315**（置信度 0.106） | 零覆盖 |
| **餐厅点餐** | **退回全量 315**（置信度 0.161） | 零覆盖 |

覆盖域上窄化工作得很好——能把 27~31 个第 52 名之后的专科件捞进候选。
**问题是目录的域**：315 个区块全部抠自 grafana / sentry / backstage / metabase /
plane / outline / airbyte / chatwoot / keycloak / cal.com / immich / medusa / shopware
——开发者工具与 SaaS 后台。**中文主流的消费、零售、履约类题目一个都够不着。**

### 自适应回退这条路本身站不住

它当初的理由是「零覆盖域上窄化是净负面，实测 −58%」（12f74707）。那个测量大概率是真的，
但**回退到全量并不能救场**：

    窄化：从 315 个里挑 60 个不对题的 → 模型在 60 个不对题的里挑
    回退：注入全量 315 个          → 模型在**前 30 个**不对题的里挑

两边都不对题，回退只是把选择面从"检索挑的 60 个"换成"目录顺序的前 30 个"。
**它没有解决零覆盖，只是换了一种失败方式**，而且换成了更没道理的那一种
（按目录顺序，不按题意）。

⚠ 这条要改之前得先想清楚：零覆盖域真正的答案不是"注入更多"或"注入更少"，
是**目录里根本没有那个东西**。补域比调阈值管用。

## 三、用户说的"全是表格"在这里显形

9 个建得很到位的业务实体，最后靠 `RecordDetail ×4` + `DataTable ×2` 呈现。

**不是模型笨——它把 社区团购 的领域模型建得很准；是它找不到别的东西可用。**
组件库那面墙上"看着都一样"和生成的应用里"全是表格"，是同一个根因的两个面。

## 四、其它观察

- **一处降级，如实上报了**（这是对的）：
  `CapabilityLlmFallback` — 能力 `intent.clarify` 的 LLM 返回空内容
  （`empty content from LLM (stream)`），回退 RAG。整趟只此一处。
- **外部检索基本没贡献**：`evidence.search` 只拿回一条
  `fallback-knowledge, score=0.6`（"RBAC 权限边界与审计日志是权限系统的基础能力"），
  而模型自己列了 5 条"仍需外部检索的缺口"（成团率口径、退款状态机、自提点分拣流程…）。
  相关性闸在拦，但拦完之后没有替代来源。
- **生图整条链没跑**：`monitor.sheet` 0ms，因为线上没配 `IMAGE_API_KEY`。
  首页仍然出了 `freeformOverview`（设计模型走的是纯文本档）。
- 页型门禁仍是"只观测不拦"，这一趟**观测到 0 处越界**——目录去重之后同族矛盾降到 7 对，
  和这一趟的干净结果是一致的。

## 五、结论与建议顺序

1. **补目录的域覆盖**（最要紧）。现在 315 个全在开发者工具/SaaS 后台一侧。
   电商履约、门店零售、教育、医疗、政务这些中文场景一个专科件都没有——
   置信度 0.106 就是这个事实的数值形式。
2. **重新审视自适应回退**。低置信度时回退全量等于回到位次决定一切；
   要么保持窄化并如实标注"本次候选可能不对题"，要么把这一档做成显式的
   "目录没有对应件"信号，让上层知道该补域而不是默默降级。
3. 生图 key 没配，视觉那一整档在线上是常关的——这跟成本估算的账要对上。
